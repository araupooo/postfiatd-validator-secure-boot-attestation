# Methodology

## Pinning

1. The LIVE main HEAD of `postfiatorg/postfiatd` was fetched via the
   GitHub API (`GET /repos/postfiatorg/postfiatd/commits/main`) at build
   start: `0085a1ff885d6a446369cf73a4430f75af22be55` (2026-10-10, 1.0.9).
   The same commit was already HEAD; it was re-fetched live, not assumed.
2. The full git tree (1,947 paths) was fetched via the API
   (`GET /repos/.../git/trees/<sha>?recursive=1`) and vendored as
   `evidence/pinned-tree-paths.txt`.
3. The 21 cited files were downloaded from `raw.githubusercontent.com`
   at the pinned commit and verified against the tree: for each file,
   the git blob SHA-1 (`SHA-1("blob <len>\0" + content)`) and the byte
   size must equal the tree entry. All 21 matched; the result is
   recorded in `evidence/pinned-tree-manifest.json` and re-checked by
   `scripts/harness/inventory_check.py` on every run.
4. The external dependency pin (`validator-keys-tool` commit
   `05742108...`) was verified live via the GitHub API.
5. Vendor specifications were checked against their primary sources
   (see `PINNED-SOURCES.md`): UEFI 2.10 ch. 32, TCG TPM 2.0 Library
   Parts 1 and 3, TCG PC Client Platform Firmware Profile v1.06 rev 52,
   NIST SP 800-155 (noted as a retired draft) and SP 1800-34, RFC 9334,
   NIST FIPS 203/204/205.

## Static analysis (MEASURED)

`scripts/harness/inventory_check.py` re-derives 31 inventory facts from
the vendored pinned sources by file/line inspection (string and regex
searches, counts, and blob-SHA verification). Each check prints its
evidence and value; the unedited log is `outputs/run_all.log` and the
structured result is `outputs/inventory_check.json`. 31/31 pass.

Line numbers in this pack were taken from the vendored copies, which
are byte-identical to the pinned tree. A claim whose line number cannot
be re-derived by the harness is not stated as a measured fact.

## Models (SIMULATED)

Four software models, all deterministic (fixed test vectors, RFC 6979
deterministic ECDSA nonces, sorted JSON keys, no timestamps, no
randomness), all standard-library Python 3 only:

- `pcr_model.py` — TPM 2.0 PCR extend rule and boot-event replay
  (6 cases, incl. tamper, reorder, truncation, bank mismatch, update).
- `quote_verify.py` — TPM2_Quote verification: AK signature, nonce,
  PCR selection, PCR digest, golden values (7 cases, incl. replay,
  wrong AK, narrowed selection, stale golden values).
- `seal_model.py` — PCR-policy sealing with a PolicyAuthorize path
  (7 cases, incl. tamper, update brittleness, forged authorization).
- `manifest_model.py` — validator manifest lifecycle with real
  secp256k1 ECDSA: rotation, replay rejection, tampered signatures,
  first-sighting acceptance, terminal revocation (8 cases).

The pure-Python ECDSA implementation (`scripts/harness/ecdsa.py`,
secp256k1 and NIST P-256) was cross-checked against OpenSSL at build
time: signatures produced by the module verify as "Verified OK" under
`openssl dgst -verify` for both curves. The test keys are fixed
constants labelled test-only and are never used outside the models.

`coverage.py` combines the inventory and model results into the
12-stage coverage matrix (`outputs/coverage.json`).

## Label discipline

Every substantive claim in this pack carries one label:

- **MEASURED** — verified against the pinned source or produced by
  executing the harness (with the output preserved in `outputs/`).
- **SIMULATED** — produced by the software models above; the model
  implements the specified behaviour but no hardware was involved.
- **UNTESTABLE** — would need validator-host hardware or host access
  that was not available; stated as an open question, never as a fact.
- **ANALYSIS** — interpretation or recommendation (used in the
  decision memo and findings severities).

No hardware measurement is claimed anywhere in this pack. The build
machine has no TPM device (`/dev/tpm*` absent), no TPM tooling
(`swtpm`/`tpm2-tools` not installed), and no enclave hardware.

## Reproduction

`scripts/run_all.sh` re-runs the whole harness and prints full SHA-256
digests of every output. `scripts/verify_digests.sh` checks every
deterministic shipped file against `SHA256SUMS`. Two shipped files are
excluded from `SHA256SUMS` by design: `outputs/run_all.log` embeds the
run timestamp and the absolute pack path, so it is not byte-reproducible;
`outputs/reproduction/COMPARISON.md` is written by
`clean_reproduce.sh` after digest verification and is not regenerated by
`run_all.sh`, so a fresh copy has no copy to check. `scripts/clean_reproduce.sh`
reproduces from a fresh copy of the pack alone: it copies the pack to a
temporary directory (excluding generated outputs and local-only files),
re-runs the harness there, verifies digests, compares every regenerated
`outputs/*.json` byte-for-byte against the committed ones, and writes
`outputs/reproduction/COMPARISON.md`. It uses no network, clones no
other repository, runs no Conan, and calls no package manager. See
`outputs/reproduction/COMPARISON.md` for the committed result.

## Limitations (honest)

- The assessment is of the pinned source tree and the documented
  deployment, not of the live validator hosts. Host firmware, TPM
  presence, Secure Boot state, and actual runtime configuration were
  not observable and are UNTESTABLE here.
- The models implement the specified TPM/manifest semantics in
  software; they validate the logic, not the hardware or the real
  postfiatd binary (the binary was not built or run — building it
  requires Conan and a full toolchain, which is out of scope for a
  lab-only harness and would not have added hardware evidence).
- Severity ratings are assessed judgement, labelled ANALYSIS.
- The deploy workflow in the pinned public source lists validator host
  IPs; this pack cites the token-by-IP mechanism by line number and
  does not list IPs in its prose. The vendored copy of `deploy.yml` is
  verbatim public source (blob-SHA verified against the pinned tree),
  so it contains the same IPs that are already public in that
  repository — no non-public host information is introduced by this pack.
